# Dark Mode Support (FreeVago) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an instant, no-reload, persisted light/dark theme toggle (Claude-style sun/moon switch) across all of FreeVago (now the only product in this repo — the municipal product that used to share it was deleted in a prior session), using the exact dark palette the user specified.

**Architecture:** Tailwind v4 class-strategy dark mode — `@custom-variant dark (&:is(.dark *));` already exists in `src/index.css` from Task 1 of the prior plan; only the `.dark { ... }` token *values* need replacing. Since every route in this app is now FreeVago, theming applies at the document root (`document.documentElement`, i.e. `<html>`) via a small `useTheme()` hook, not scoped per-page. Preference persists to `localStorage["freevago-theme"]`; absent key means "follow system," present key means an explicit user choice that wins over system from then on. A tiny inline script in `index.html` applies the class synchronously before React mounts, to avoid a flash of the wrong theme on load.

**Tech Stack:** React 19, TypeScript, Tailwind v4 CSS variables, lucide-react (already a dependency, for Sun/Moon icons).

**Spec:** User's request delivered 2026-08-19 (same session as the prior chat-estetica plan). Exact dark values given: `bg-base #12171A`, `primary #1B5A6B`, `accent #E8955C` (unchanged), `text #EDEFEC`, `border/neutro #2A312E`. Strategy: `class`, not `media`. Initial default: `prefers-color-scheme`; explicit choice overrides and persists. Toggle: sun/moon, in chat + resultados headers, smooth icon transition, smooth ~150-200ms screen transition on background-color/color/border-color. Logo: automatic `onDark` variant switch (already built in `Logo.tsx`, just needs wiring). No hardcoded light-mode colors left behind, especially in `ProposalCard`/markdown tables.

## Global Constraints

- Only the 5 tokens the user specified have fixed values (`--background #12171A`, `--primary #1B5A6B`, `--accent #E8955C` unchanged, `--foreground #EDEFEC`, `--border #2A312E`/`--input #2A312E`). Every other `.dark` token (`--card`, `--popover`, `--primary-foreground`, `--primary-soft`, `--secondary`, `--secondary-foreground`, `--muted`, `--muted-foreground`, `--accent-foreground`, `--accent-soft`, `--ring`) is **derived** below, following the same relationships the light-mode tokens already use (Task 1 of the prior plan). These derived values are documented explicitly in Task 2 — not silently invented.
- `--destructive`, `--chart-*`, `--sidebar-*` in the `.dark` block stay exactly as they are today (untouched, out of scope — `--chart-*`/`--sidebar-*` are dead weight now that the municipal product using them is deleted, but removing them is a separate cleanup, not part of this plan).
- No test framework exists in this project (unchanged from the prior plan). Verification is `npm run build` per task, plus manual browser verification as the final step (this plan's own "Task 4").
- Theme state lives in `document.documentElement`'s `class` list (`dark` present/absent) — never in a per-page wrapper. Every FreeVago page (`AccessPage`, `ChatPage`, `ResultsPage`) calls `useTheme()` on mount to apply/sync it; only `ChatPage` and `ResultsPage` render the actual `<ThemeToggle>` button, per the user's spec.
- `localStorage` key is exactly `"freevago-theme"`, values exactly `"light"` or `"dark"` (never a literal `"system"` string — "system" is represented by the *absence* of the key, which is simpler and behaviorally identical to a tri-state model while avoiding an extra resolution step).
- Respect `prefers-reduced-motion`: the icon crossfade and the screen-wide color transition both collapse to nearly-instant under reduced motion, consistent with how the rest of this codebase already handles it (`src/index.css`'s existing `@media (prefers-reduced-motion: reduce)` block).

- [ ] **Step 1: Create `src/lib/theme.ts`**

```ts
// src/lib/theme.ts
export type Theme = "light" | "dark";

const STORAGE_KEY = "freevago-theme";

export function getSystemTheme(): Theme {
  if (typeof window === "undefined") return "light";
  return window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
}

export function getStoredTheme(): Theme | null {
  if (typeof window === "undefined") return null;
  const raw = localStorage.getItem(STORAGE_KEY);
  return raw === "light" || raw === "dark" ? raw : null;
}

export function resolveInitialTheme(): Theme {
  return getStoredTheme() ?? getSystemTheme();
}

export function applyTheme(theme: Theme): void {
  document.documentElement.classList.toggle("dark", theme === "dark");
}

export function persistTheme(theme: Theme): void {
  localStorage.setItem(STORAGE_KEY, theme);
}
```

- [ ] **Step 2: Create `src/lib/useTheme.ts`**

**Design note (post-Task-3 correction — see plan-level ruling below):** this hook is called independently in more than one place at once on the same page (e.g. `chat.page.tsx` reads `theme` directly for the `Logo` variant, and separately renders `<ThemeToggle />`, which calls `useTheme()` again internally). A plain per-instance `useState` gives each call site its own isolated state — clicking the toggle updates `ThemeToggle`'s own state and correctly flips the `dark` class (so CSS-driven styling updates everywhere), but `chat.page.tsx`'s own `theme` variable never learns about the click, so anything driven by the JS `theme` value (the `Logo`'s `variant` prop) goes stale until remount. The hook needs one shared module-level store that every instance reads via `useSyncExternalStore`, so all instances re-render together on every change:

```ts
// src/lib/useTheme.ts
import { useSyncExternalStore } from "react";

import { applyTheme, getStoredTheme, getSystemTheme, persistTheme, resolveInitialTheme, type Theme } from "./theme";

type Listener = () => void;

let currentTheme: Theme = resolveInitialTheme();
const listeners = new Set<Listener>();

function notify(): void {
  listeners.forEach((listener) => listener());
}

function subscribe(listener: Listener): () => void {
  listeners.add(listener);
  return () => listeners.delete(listener);
}

function getSnapshot(): Theme {
  return currentTheme;
}

function setGlobalTheme(next: Theme): void {
  currentTheme = next;
  applyTheme(next);
  notify();
}

let systemListenerAttached = false;

function ensureSystemListener(): void {
  if (systemListenerAttached || typeof window === "undefined") return;
  systemListenerAttached = true;

  const media = window.matchMedia("(prefers-color-scheme: dark)");
  media.addEventListener("change", () => {
    if (getStoredTheme() !== null) return;
    setGlobalTheme(getSystemTheme());
  });
}

if (typeof window !== "undefined") {
  applyTheme(currentTheme);
  ensureSystemListener();
}

export function useTheme(): { theme: Theme; setTheme: (next: Theme) => void } {
  const theme = useSyncExternalStore(subscribe, getSnapshot);

  function setTheme(next: Theme): void {
    persistTheme(next);
    setGlobalTheme(next);
  }

  return { theme, setTheme };
}
```

Every instance of `useTheme()` across the whole app now shares one `currentTheme` value via the module-level store — `setTheme` from any instance (the toggle button) updates it once, `notify()` tells every subscribed component to re-render, and `useSyncExternalStore` is exactly the React-blessed primitive for "external mutable state read by multiple components," avoiding both a Context provider (unnecessary ceremony for two functions and one value) and the stale-instance bug.

- [ ] **Step 3: Create `src/components/ThemeToggle.tsx`**

```tsx
// src/components/ThemeToggle.tsx
import { Moon, Sun } from "lucide-react";

import { Button } from "@/components/ui/button";
import { useTheme } from "@/lib/useTheme";

export function ThemeToggle() {
  const { theme, setTheme } = useTheme();
  const isDark = theme === "dark";

  return (
    <Button
      type="button"
      variant="ghost"
      size="icon"
      aria-label={isDark ? "Cambiar a modo claro" : "Cambiar a modo oscuro"}
      onClick={() => setTheme(isDark ? "light" : "dark")}
      className="relative overflow-hidden"
    >
      <Sun
        className={`fv-theme-toggle-icon absolute size-4 transition-all duration-200 ${
          isDark ? "-rotate-90 scale-0 opacity-0" : "rotate-0 scale-100 opacity-100"
        }`}
      />
      <Moon
        className={`fv-theme-toggle-icon absolute size-4 transition-all duration-200 ${
          isDark ? "rotate-0 scale-100 opacity-100" : "rotate-90 scale-0 opacity-0"
        }`}
      />
    </Button>
  );
}
```
